## ★★ 本包（Vidu）的适配 —— **先读这一节**

> 本包没有单独的「渠道差异层」文件，渠道取值在 **`SKILL.md §5`** ＋ **`references/vidu-平台机制.md`**。
> 主线的五步骨架在本包里这样落地：

| 步 | 本包怎么做 |
|---|---|
| **① 预检** | `python scripts/vidu_edge.py up --wait 60` / `status` —— 确认**端口通 ＋ 已登录**（未登录 → `INIT.md`） |
| **② 资产就位** | ★ **直提会自动上传并绑定**（顺序与提示词 `pnN`/`vmN` 严格一致）：`scripts/vidu_api.py run`；<br>**主体库**（可选，让角色跨组更稳）：`scripts/vidu_refs.py import` |
| **③ 自检门** | `python scripts/shot_language_check.py "<项目>/00_剧本与提示词"` |
| **④ 提交** | ★ **`--mode nopeak` = 闲时（0 积分）**。单组 → `vidu_api.py run`；**批量 → `vidu_queue.py run`**（自动盯「进行中」补投，榨干每天 200 条） |
| **⑤ 产物核对** | `python scripts/vidu_daily.py --jobs "<项目>/_vidu渠道/jobs_vidu.json" --by-ep` —— 下载无水印成片 ＋ 按组/分集重命名 ＋ 出日报 |

- ★ **跑完必须关实例**：`python scripts/vidu_edge.py down`（本渠道不计费，但不关会占着浏览器与登录会话）。
- ⚠ **全部命令必须在沙箱外执行**（解释器用系统 Python，见 `INIT.md`）。
- ⚠ 本卡下文凡提"各渠道传法不同 / 并发见差异层 / 按小时计费"的地方，本包按上表执行。

**① 进入 / 跳过条件**
- 必须做：Phase 6 的提示词**已过零计费自检门**。
  ★ **默认口径（2026-10-04）**：**不再等 CP-4 批准、不再询问计费** —— 提示词过门即提交。
- ⛔ 跳过：该组 `.mp4` 已存在且 >1KB（**断点续跑自动跳过，不重复计费**）。
- ⛔ **不得跳过**：**预检、自检门**二者任一都不能省 —— 这两道**零计费**，拦的是"白花钱"（模型名写错 / 资产没到位 / 提示词不过门）。

**② 输入**

| 类别 | 路径 |
|---|---|
| ★ 输入 | `00_剧本与提示词/第N集.txt`（Phase 6 提示词） |
| ★ 输入 | `00_剧本与提示词/_分镜组规格.json`（**下游门禁唯一事实来源**） |
| 输入 | `01_资产库/` 资产（**参考图必须"真实生成过"，不是 dry-run 占位**） |
| 渠道资源 | 图床 / 云实例 / 资产池（→ 差异层的「资源准备」） |

**③ 做什么 —— 五步骨架（所有渠道相同，只是每步做法不同）**

```text
① 预检 / 网络体检（零计费） → ② 资产就位 → ③ 零计费自检门
     → ④ 提交出片 → ⑤ 产物核对（★ 默认只核产物完整性）
```

| 步 | 做什么 | 关键点 |
|---|---|---|
| ① 预检 | 渠道探活（账号 / 端点 / 余额 / 模型可用性） | ★ **开工先探活** —— 有的渠道常处于未登录/401 状态，别跑一半才发现 |
| ② 资产就位 | 参考图/音色按渠道传法就位（上传图床 / 预推资产池 / 写进 prompt） | 顺序与 Phase 6 提示词里的编号**严格一致**（改动一处即两处生效）。★ **有多形象角色时，上传前必跑 `tools/wardrobe_check.py`** —— 传错形象图 = 白烧钱 + 着装穿帮，且服务端不留痕迹 |
| ③ 自检门 | 再跑一次 Phase 6 的门（**零计费**） | 全绿才允许提交。★ 含 **`wardrobe_check.py`**（形象一致性，多形象角色时） |
| ④ 提交出片 | 提交 → 轮询 → 下载 | 见下「命令骨架」 |
| ⑤ 产物核对 | ★ **默认口径：只核产物完整性**（缺片 / 多片 / 落错集 / 规格统一 —— 纯本地、零计费） | ⛔ **抽帧目检 / 有声窗 / 画幅时长比对 / 音频台词核验，默认一律不做**。用户点名要查质量时才补做（抽帧 4 帧拼条最快，一眼看出道具状态、在场人、有没有换脸） |

```bash
python main.py rerun --project "<项目名>" --type video --id "2_2_标准" --step 7.1-7.3
```

旧产物先移到 `<项目>/_重做历史/<type>_<id>_<时间戳>/`，节点状态重置 `pending`，新产物写回原路径。

## ⚠ 长任务纪律（P0，别踩）

1. 启动即在 `_出片记录/` **登记 pid**；批量**必带批次日志**（日志里的 `task_id` 是任务被杀后**唯一**补救凭据）。
2. ⚠ **别用 `| tail` 接管道跑批量** —— 管道一关就把进程带走，`task_id` 全丢。
3. **停任务 ≠ 省钱**：已提交到服务端的组照常跑、照常计费。停完必须**收尾**：
   补下已付费产物 → 对台账找「已提交无产物」的组 → 补跑（已成功的不会重复计费）。
4. ⛔ **绝不去 interrupt 别人的作业**（云实例可能被别的会话占用）。
5. ⛔ **跑完必须关实例**（按小时计费的渠道尤其）。

## ★ 差异层必须覆盖的点（漏了不报错，只会静默跑错）

| 必须覆盖 | 说明 |
|---|---|
| **① 资源准备** | 图床预热 / 云实例开关 / 资产池预推 —— 各渠道形态完全不同 |
| **② 自检门的具体命令** | 门名 + 通过判据（含老项目放行开关） |
| **③ 提交与并发策略** | 并发数、限流退避、**提交间隔**（有的渠道「不能连发、要静默 N 秒」）。★ **节奏原则见主线 `SKILL.md` §5.5「提交与生成解耦」**：提交完一个隔「提交间隔」就提交下一个、**⛔ 不等它生成**；生成期间并发轮询、成品一出立刻下载。差异层只写**本渠道的间隔秒数与并发上限** |
| **④ 失败信号与捞回** | ★ 哪些是**假报错**（模型名错伪装成限流/余额）、哪些**能捞**（专门的捞回脚本）、哪些**只能重跑** |
| **⑤ 产物核对脚本** | ★ **默认只核产物完整性**（齐不齐 / 规格统不统一）。抽帧与音频核验**默认不做**；需要时才上各渠道体检脚本（如「有声窗 ≥75%」在某渠道是**假警报**，得用专门的 6s 滑窗脚本） |
| **⑥ 计费口径与成本闸** | 按次 / 按秒 / 按小时；★ **以实测对账为准，不抄价目表** |
| **⑦ 参考图传法** | 走 `reference_images` 字段 / 写进 prompt / 先上传得 URL（URL 有效期也要写） |

> ⛔ 差异层**不得另立一套**命名 / 候选 / 落盘 / 长任务纪律（见 `SKILL.md` §5.1–§5.3）。

## 排障速查（跨渠道通用）

| 现象 | 原因 / 处理 |
|---|---|
| `CP-4 未批准` | ★ **默认口径下不该出现**（已不征询）；真遇到就 `check --point 4` 看报告，再 `--approve` |
| 视频参考图为空 | 本集资产图**还没真实生成**（不是 dry-run 占位） |
| 成片太短 | ★ **不是档位问题，是台词太少**（秒数由对白驱动）→ **合并回相邻组** |
| 门禁一直红 | **规格文件过时** → 按提示词重建（见 Phase 6 §⑤） |
| 报错像限流/余额 | ★ **先怀疑模型标识写错** —— 上游常把「模型名错」伪装成限流或余额不足 |
| 轮询超时 | → 差异层的「失败信号」；有的能捞、有的只能重跑 |

## ★ 失败归因（必做，⛔ 不要笼统说"失败了"）

| 现象 | 判断 | 处理 |
|---|---|---|
| **真人人脸 / 肖像审核**报错 | ★ **交叉推断**：把各组用到的资产摆开 —— 例 A/B/C/D 四角色，**ACD 的组正常、含 B 的组报错** ⇒ **怀疑 B 的资产不过审**。<br>判据：**只在失败组出现、从未在任何成功组出现**的资产 = 头号可疑 | **要求用户改该资产**（换图 / 重出）→ 只重跑受影响的组 |
| **提示词违规 / 敏感词** | 提示词本身的问题 | ★ **直接重写该组提示词并重提**，⛔ **不用问用户** |
| **额度 / 积分不足** | 额度被拒 | **记录断点 → 让用户切换账号 → 新账号从断点继续**；⚠ **先前生成的必须等完成并下载后**再切号 |
| 其它 | 逐条看返回原文 | 记进报告，让用户决策 |

> ★ 先**分类**再处理：**分类错了，返工就白做**。同一个"失败"可能是资产问题、提示词问题或额度问题，
> 处理方式完全不同。
