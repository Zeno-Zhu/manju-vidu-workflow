## Phase 2｜资产盘点

**① 进入 / 跳过条件**
- 必须做：没有可用的盘点清单（`资产盘点.json` 或等价的手写清单）。
- ⛔ 跳过：已有 `资产盘点.json`（或项目侧已有的 `_资产盘点.md`）**且**用户确认过 ——
  直接进 Phase 3。
- ★ **本阶段一定会有一次「等用户确认」**（CP-1），因为盘点结果决定后面全部投入。

**② 输入与权威规范**

| 类别 | 路径 |
|---|---|
| 输入 | `00_剧本与提示词/剧本/<项目名>剧本带对话时长.md`（Phase 1.2 产物） |
| 输入 | 剧本设定（`项目配置.json` 的 `setting_path`，可选） |
| **规范（先行词）** | `prompts/资产盘点先行词.md` ← 分批盘点用的系统提示词 |
| **规范（汇总 schema）** | `prompts/资产盘点汇总.md` ← 合并去重时的字段口径 |

> ★ **两份规范缺一不可**：先行词定义「怎么读剧本找资产」，汇总定义「合并后长什么样」。
> 只给一份 ⇒ 分批结果没法对齐。

**③ 做什么**

```bash
python main.py run --project "<项目名>" --step 2.1-2.3
```

拆开看，每一步在干什么：

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| 2.1 | **组装盘点输入包** | 把全剧文本 + 设定 + 集数清单打成一个包。**不做判断**，纯打包 |
| 2.2 | **按集窗口分批盘点** | 每窗口**默认 6 集**（`batch.asset_episodes_per_window`）。**必须分批** —— 全剧一次塞进去会漏资产 |
| 2.3 | **合并去重** | 跨窗口同名资产合并（`normalize_asset_name` 归一），生成最终清单 |

**④ 产出**

| 产物 | 路径 | 说明 |
|---|---|---|
| 输入包 | `00_剧本与提示词/剧本/资产盘点_输入包.json` | 2.1 |
| 分批结果 | `00_剧本与提示词/剧本/资产盘点分批/*.json` | 2.2，**一窗口一份** |
| ★ **最终清单** | `00_剧本与提示词/剧本/资产盘点.json` | 2.3 |

清单结构（下游按这个结构取用）：

```jsonc
{
  "全局专属资产盘点": {
    "角色和对应音色资产": [{ "角色资产名": "…", "角色音色名": "…" }],
    "场景资产":           [{ "场景资产名": "…" }],
    "道具资产":           [{ "道具资产名": "…", "商品": true }]   // ★ 商品要显式标
  },
  "分卷资产列表": [ … ]     // 只在特定集出现的资产
}
```

⛔ **不产出**：提示词、图片、任何 01_资产库 内容 —— 那是 Phase 3–4 的事。

**⑤ 闸门｜CP-1 资产盘点确认**（报告，**非 gate**）
- **判据**：角色 / 场景 / 道具三张清单是否符合预期。
- **谁批**：**用户**。报告会明确列出三张清单。
- **没过怎么办**：★ **直接编辑 `资产盘点.json` 再重跑 2.3**（不要重跑 2.2 —— 白烧 LLM 调用）。
- **重点核对对象**：**商品资产**（剧情电商要重点展示，需补 `"商品": true`）与**重点角色**。
- 批准：`python main.py check --project "<项目名>" --point 1 --approve`

## ★ 角色「多服装 / 多状态」要结合剧本分析（2026-10-11 定）

盘点**不是**把剧本里出现的元素照抄一遍 —— 对**有多套服装 / 多个阶段形态**的角色，
必须**逐个过剧本**，找出他**真正出现过的场合与阶段**（婚礼 / 丧礼 / 上班 / 居家 / 受伤后 / 变身后…），
据此列出**实际需要的服装 / 状态**，并写清**出现在第几集 / 什么场合**。

- ⛔ **不要凭想象给角色加版本** —— 剧本里没用到的状态**不盘点、不制作**。
- **数量硬规矩**：同一角色正式设定板 **≤3 个，优先 2 个**；**能一张（不换装）满足使用，就只做一张**；
  需要超过 3 个 ⇒ **先与用户确认**。
- ⛔ **音色不随服装 / 状态拆分**（同一角色共用一份音色资产）。
- 产出里要能一眼看出：**角色 → 需要的服装 / 状态 → 出现集数**。

### ★★ 多形象角色必须落「形象规划」（2026-10-11 定，正式流程）

只要有角色要出 ≥2 张形象图，盘点确认时**同步产出**：

`<项目>/00_剧本与提示词/_形象规划.json`

```jsonc
{
  "characters": {
    "王桂兰": { "images": [
      { "file": "王桂兰.png",       "state": "日常（素色毛衣）", "scenes": ["1-1","1-2","1-3","1-4","1-5","1-8"] },
      { "file": "王桂兰-演出服.png", "state": "红色演出服",      "scenes": ["1-6","1-7"] }
    ]}
  },
  "group_scenes": { "9_8_H3": "1-8" },   // 补镜头等规格外组的场号归属（可选）
  "ignore_prefixes": ["6_"]              // 已交付组豁免（可选）
}
```

- **角色 → 形象图文件 → 适用场号范围**，三者逐字对应；**同一场只能绑一张图**（范围不得重叠）。
- **与 CP-1 一并交用户确认**（哪一集换装、大部分节点穿什么，**提前规划**，不许临场定）。
- 文件名规范：`<语义名>-<状态>.png`（如 `林月华-婚礼.png`）；主形象不带后缀。
- 这是出片前**形象一致性检查**（`tools/wardrobe_check.py`，见 Phase 6/7）的唯一输入。
- ★ **全剧所有角色都只有一张形象图 ⇒ 规划可省、检查自动跳过**。
