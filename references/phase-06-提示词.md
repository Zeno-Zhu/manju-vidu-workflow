## Phase 6｜视频提示词

**① 进入 / 跳过条件**
- 必须做：Phase 5 已出分镜表，或**用户直接给了剧本 + 资产**（跳过 Phase 0–5 也成立）。
- ⛔ 跳过：该集的提示词文件（`00_剧本与提示词/第N集.txt`）已存在且**过过自检门**。
- ⛔ **Phase 5 的三份产物都不能直接当提示词**（5.1 TSV / 5.2 统一制作基准 / 5.3 镜头规划）—— 它们是「制作依据」，
  提示词必须按下面的三步**按渠道规范正式生产**。
- ★ **回退禁止**：`gen_prompts.py`（DeepSeek 逐组生成）**已废弃**，不要再跑。

**② 输入与权威规范**

| 类别 | 路径 |
|---|---|
| 输入 | 剧本（带对话时长标注）`00_剧本与提示词/<剧本>.md` |
| 输入 | 项目资产库 `01_资产库/`（**决定参考图编号 `<Picture N>` / `<Subject N>`**） |
| 输入 | 场景资产映射（人工裁决产物，通常 `_场景资产映射.json`） |
| ★ 输入 | **5.2《统一制作基准》** `00_剧本与提示词/EPxx/分镜组/EPxx_统一制作基准.md` ＋ **5.3 镜头规划** `EPxx_镜头规划_{制式}.tsv` —— 站位 / 光影 / 语气 / **摄影设计**，标准提示词直接取用 |
| **拆组规格** | 拆组工具产出的 `_分镜组规格.json`（★ 下游门禁的**唯一事实来源**） |
| ★ **制式（方法论）** | **按本组用哪套制式** → 主线 `references/制式-标准.md` / `-自己人.md` / `-H3.md`（该组**有打斗**时另读 `-打斗.md`）。**同一制式跨渠道共用，⛔ 不随渠道分叉** |
| ★★ **镜头语言（跨制式通用层）** | `references/镜头语言.md` —— **任何制式都要先过这一层**：一镜三件套 / **运镜是戏剧任务的函数（⛔ 不设配额）** / 每个运镜交代落点 / 峰值镜头 / 跨组承接（景别与运镜同时承接）/ **反回声三类** |
| ★ **书写规范（输出模板）** | **按渠道**（各渠道**整套不同**）→ 见当前渠道差异层的「Phase 6」；它是**本渠道所选制式的落地稿** |
| ★ **允许的极端情况下手写** | 若项目是「无分集长剧本」，工具会按场分文件（判据见下） |

> ⛔ **不得交叉读规范**：拿 A 渠道的规范写 B 渠道的提示词，是音色/画风错乱的**头号来源**。

> ★ **路径澄清（2026-10-11，防误改）**：**提示词正文文件 `第N集.txt` 归 `00_剧本与提示词/` 根目录**
> （工具 `h3_batch_all.py` 等按此发现）；**信息类产物**（分镜表 / 制作规划 / 素材清单）才归 `00_剧本与提示词/EPxx/`。
> 两者**并存是设计，不是冲突**，⛔ 别把 `第N集.txt` 搬进 `EPxx/`（会断工具发现）。

**③ 做什么**（三步，所有渠道同构，只是每步取值不同）

```text
① 确定性拆组（零 LLM）→ ② 逐组书写提示词 → ③ 过该渠道的零计费自检门 → ④ 出提交单
```

**① 确定性拆组**（纯工具，几秒）

| 做什么 | 关键点 |
|---|---|
| 按「集 / 场」切出**出片单元** | 每个单元 = 一个提示词组 = 一个文件里的一段 |
| 按**时长需求**吸附档位 | ★ **档位按「对白需要多少秒」取最小够用档**，别一律顶到上限 |
| 扫资产库，猜每场的场景资产 | 猜错要**人工裁决**后写映射文件**重跑**，别在提示词里硬改 |
| 输出规格 + 组名 | 组名 `{集}_{组}_{渠道标记}`，**组号纯数字** |

★ **判据（是否需要按场拆）**：剧本站内**场号首段只有一个**（无分集）或单集过大
（`> 180s` / `> 20 组`）⇒ **按场分文件**，一场 = 一个出片单元。
有分集的成片剧本 ⇒ **一集一个文件**。工具 `--mode auto` 会自动判并打印分集策略。

⛔ **组号必须纯数字**（`1_1b` 会被预检查拒）；变体只能在渠道标记**之后**加后缀。

**② 逐组书写**（IDE 直写，不调 LLM API —— 2026-09-26 起）

- 写前**通读**当前渠道的规范全文（不是凭记忆），规范是唯一权威。
- **一次写 1 场（3–9 组），写完立刻跑单集自检**；⛔ 不要一口气写完整季再检测（错误累积、返工翻倍）。
- 产出：`00_剧本与提示词/第N集.txt`（一集一份，本集各组按序）。

**③ 过自检门**（**硬 gate**，不通过**不许出片**）

各渠道的**门数与命令不同**，但骨架一致 —— 通常包括：
拆组一致性 / 资产引用完整性 / 音色标签审计 / 语速与节奏体检 / 跨组承接检测 / 内容层审核。
**全部写完后再跑一次项目级总门**（不是逐集跑）。

★ **一门跨渠道通用、所有渠道都要跑的零计费门**（2026-10-10 提升为正式步骤；
★ **2026-10-11 判据升级**：**组首取值从「景别」扩为「景别＋运镜」**；新增**组内连续 ≥3 镜同运镜**；
新增 **A2 阻断**：**每镜必须写运镜状态**（固定也要写 `static camera`）；
⛔ **删除判据 C（运镜覆盖率 ≥60%）** —— 它是伪装成"下限门"的**创作配额**；
★ **退出码三态**：`0 = PASS`（告警只呈现，**允许出片**）｜`2 = BLOCK`（仅字段缺失等结构性错误）｜
`1 = 仅 --strict`（重要项目 / 交付前想把告警也清干净时用））：

```bash
python tools/shot_language_check.py "<项目>/00_剧本与提示词"     # 或单集：…/第N集.txt
```

管「**画面别太平 / 别长时间停在一个拍摄角度**」，**自动识别 H3 与即梦两种语法**，查七项：
每镜**三项写全**（景别 · 机位角度 · **运镜状态，固定也要写**） · 特写数 · 单镜组 · 组内连续同景别 ·
**跨组高频构图套件与相邻组连续同首镜**。**退出码 1 = 有阻断或告警**。
权威判据 = `prompts/即梦20镜头写作避坑.md`（九条，本工具即其机器化版本）。
⚠ 它只查**形式**（写没写 / 密不密 / 重不重复）；**峰值选得对不对、景别合不合理**仍须人工判。

**★ 第二门跨渠道通用（2026-10-11 新增）：形象（服装/状态）一致性检查**

```bash
python tools/wardrobe_check.py "<项目>"    # 自动扫作业单 + H3 提示词 + _形象规划.json
```

管「**同一角色的多张形象图有没有传错场**」—— 参考图与提示词的服装描述打架时，
模型有时跟图、有时跟文 ⇒ **同一叙事日着装漂移**（实测：米色毛衣主形象 + 红色演出服描述，
云鲸多数跟图出米色、H3 跟文出红）。查四项：

| 查什么 | 判据 |
|---|---|
| 规划存在性 | `01_资产库` 有多形象角色（`<语义名>-<状态>` 前缀同名）但 `_形象规划.json` 缺失 ⇒ **阻断，先规划后出片** |
| 规划完整性 | 规划引用的形象图文件不存在；同角色各形象的场号范围重叠；多形象角色漏登记 |
| 绑定一致性 | 每组实际绑定的形象图（作业单 refs / H3 `<Subject> is 资产名`）≠ 规划为该场指定的图 ⇒ **传错形象图，阻断** |
| 规划覆盖 | 组出现在规划未覆盖的场 ⇒ 告警 |

- **全剧所有角色都只有一张形象图 ⇒ 自动跳过、exit 0**（用户定的口径：单形象无需检查）。
- 已交付组用规划里 `ignore_prefixes` 豁免；**新组不许加豁免**。
- 规划 schema 见 Phase 2 卡「多形象角色必须落形象规划」。**退出码 1 = 有阻断**。

**④ 出提交单**
- 提交单 = 「该集的 API 上传文档」。**某组要重出时，只启动那一集的提交单**，不重跑全季。

**④ 产出**

| 产物 | 路径 |
|---|---|
| ★ **提示词** | `00_剧本与提示词/第N集.txt`（一集一份） |
| ★ **拆组规格** | `00_剧本与提示词/_分镜组规格.json`（**下游门禁唯一事实来源**） |
| 场景资产映射 | `<项目>/00_剧本与提示词/_场景资产映射.json`（人工裁决后落盘） |
| 提交单 | 该渠道约定的位置（→ 差异层） |

⛔ **不产出**：任何 `.mp4`（那是 Phase 7）。
⛔ **不覆盖**已有提示词文件 —— 改一组就改那一组，别整文件重写。

**⑤ 闸门**

| 门 | 时机 | 类型 | 谁批 | 没过怎么办 |
|---|---|---|---|---|
| **零计费自检门** | 提示词写完、**提交之前** | 🔒 **gate** | 工具（**零计费、可反复跑**） | 照输出的「修法」改完重跑；**全绿才进 Phase 7** |

> ★ **规格文件会过时**：手工拆过组 / 改过时长后，门禁会一直红。
> 正确修法是**按提示词重建规格**（工具 `rebuild_spec`），⛔ **不要重跑拆组脚本**

## ★ 差异层必须覆盖的点（漏了不报错，只会静默跑错）

| 必须覆盖 | 说明 |
|---|---|
| **⓪ 本渠道用哪套制式** | 声明是 `制式-标准` / `-自己人` / `-H3` 中的哪套（**打斗是叠加制式，不用单独声明**）；＋ 声明 **`锚定主线版本`** |
| **① 用哪几份规范文件** | 各渠道**整套不同**，要列**文件名 + 组合方式**（可能有「主线规范 + 固定后缀」两段拼接） |
| **② 组名后缀 / 风格线** | 如 `_H3` / `_标准` / `_自己人`；若有两条风格线，必须说明**是否三处同款** |

| **⑤ 该渠道特有的书写禁令** | 如「不能传音频 ⇒ 音频引用是悬空的」「某写法会导致吞台词」 |

> ⛔ 差异层**不得另立一套**与主线冲突的命名 / 落盘 / 长任务纪律（见 `SKILL.md` §5）。

## 2026-10-15 补录 · 视频提示词的三条输入边界（实测 337 组）

1. ★★ **逐组调用时的输入边界**（三种错法都实测过）：
   - 只喂**三列 TSV** ⇒ 模型**自己编角色名**（万集被写成"平安"，从"平安饭馆"猜的）；
   - 把**整集剧本**塞进去 ⇒ 模型**重排分组**、一个文件吐 3 组提示词、ID 全对不上；
   - ✅ **正解** = 逐组调用 ＋ **按 start/end 锚点在剧本里切片**给出**本组剧本片段**
     ＋ 明确"**只输出本组一份**，⛔ 不要其他组、不要优化建议"。
2. ★★★ **必须给「资产白名单」**（取自 `_common.reference_assets()`，与 Phase 7 的 `pnN` 编号同源）。
   不给白名单时模型会自造「米店老板 / 抹布 / 送货单 / 四碗面 / 平板」等**查无此物**的资产名 ——
   实测 302 个图片名里大量是编的，**Phase 7 一旦缺图就整组中止**。
   白名单里还要写明：**名称必须与白名单逐字一致**（如 `胖婶`，不要写「胖婶人物资产」）；
   画面里出现但白名单没有的人，**用群像资产代替**，⛔ 不要新造名字。
3. ★★ **【统一风格模块】要确定性替换**为本剧权威风格串 —— 模型会拆散主干、把专属风格混进大词层。
4. ★ **批量 LLM 调用要自起并发**：工作流的 `run_many_nodes` / `run_6_1` 是**串行 for 循环**；
   337 组串行要数小时。自起 `ThreadPoolExecutor`（实测并发 8）压到 **15 分钟**。
5. ⚠ **模板文件要先体检**：`steps/step_6.run_6_1()` 引用的 《标准模板提示词》（**本包不含该稿**）曾**不存在**
   ⇒ 6.1 必失败。开工前把该步依赖的 prompts 文件逐个 `os.path.exists` 查一遍。
