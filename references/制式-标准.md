# 制式 · 标准（即梦系 · △ 语法）

> ⚠ **本包主制式是「自己人」**（见 ）。本文件**只作方法论引用而附带** ——
> 引用它的地方是「跨组衔接与站位继承」「分层万能公式 / 时长容量 / 红线细节」。
> ⛔ 本包**不提供「标准」制式**（逐 `△` 写景别的那种）；用户若要，按 `prompts/提示词最小改造准则.md` 接入。

> **制式层** 是横在「主线」与「渠道」之间的方法论层：**同一套制式跨多个渠道复用**。
> 本文件是「标准制式」的**唯一方法论入口**。改方法论**改这里 ＋ 权威规范底座**，⛔ 不改各渠道 skill。
> 归属判据见 主线 PRD（本包不含） §4.1：**换渠道仍成立 ⇒ 制式层**。

**锚定主线版本**：`2026-10-10`

## 一、这是什么制式

**标准 = 写稿人控镜头**：逐 `△` 显式写清「景别 ＋ 机位/角度 ＋ 运镜方向与落点」，
镜头调度由**写稿人**决定（与「自己人」相反 —— 那套把镜头权交给模型）。

**语法形态**：`△`（三角）分镜单元 ＋ 显式机位/运镜描述。`△` 是**镜头单元的切分标记**，
不是台词单位 —— 一句台词可以跨 `△`，一个 `△` 也可以承载多句台词（但**台词 ≥4 句时不得只用 1 个 △**，见 §三）。

**覆盖渠道**：云鲸（即梦2.5）· 器灵 · libtv · vidu · 迪拜 · 锦行 · 即梦2.0
（各渠道 skill 自己声明「本渠道用标准制式」＋输出模板差异；本节只作一览，权威路由见 `routing-table.md`。）

## 三、共用方法论（跨渠道不变，详文在底座）

> 以下只列**骨架与判据**；逐条细节**以底座 `通用提示词.txt` 为唯一权威**，本文件不复述。

### 3.1 分层万能公式（底座 §四）

```
第一层  分镜组级叙事导演公式 —— 剧情与台词 / 叙事任务与信息释放 / 人物目标与交流关系 /
                             现场行为与空间 / 整体表演节奏与摄影视觉构想 / 视觉落点与结束状态
第二层  镜头级「叙事·表演·摄影」联合公式
第三层  跨镜头连续性公式
（＋ 条件参数）
```

### 3.2 时长与容量（底座 §五）

- **分镜组时长范围 / 上游时长 / 对白容量 / 镜头数量 / 台词承载硬判据 / 时间标注** 均在底座定。
- ★ **台词承载硬判据**：台词达到**四句及以上**的分镜组，必须按说话人切换 / 情绪转折 / 信息落点**增切镜头**。
- ★ **有效时长**：`△ 数 × 1.2s ≤ 声明时长`（每个 `△` 至少 1.2s）。
- 时长档位怎么吸附：见主线 §二 Phase 6 ＋ 渠道侧「时长口径」。

### 3.3 红线（底座 §六）

当前镜头内容 / 人物固定外观 / **主体实名绑定** —— 三者不得为叙事效果让位。

★ **人物外观只做「资产绑定」，⛔ 不写外貌（2026-10-12）** —— 底座 §6.2 是唯一权威：
已有角色视觉资产时，`@资产名` 引用**只写名字 ＋ 绑定**，
⛔ **不写五官 / 体型 / 发型 / 服装款式 / 服装颜色**。
理由：文字**上限 = 与图一致（零增益）**，**风险无上限**（与图不符即矛盾指令 → 人物 / 服装漂移）。
**例外**：服装 / 配饰**特写**或需**材质质感**时可写材质，⛔ 仍不写颜色与形态。
（H3 侧同款条款：`制式-H3.md` §3.7。）

### 3.4 空间与站位（底座 §七）

场外空间锚点 / **真实站位**（谁在哪、站还是坐、离谁多远、持物、是否接触）/ 画面构图 /
站位变化 / **空间站位说明【条件触发】**。
★ 见 §五「跨组衔接与站位继承」—— 这是 2026-10-10 上浮到主线的共同口径。

### 3.5 视线与方向性物件（底座 §八）

视线关系 / 跨空间交流 / 方向性物件（手机·书本·文件·屏幕 —— 不得反向持握、不得背面出正面内容）。

### 3.6 光影·色调·连续性（底座 §九 起）

场景光影、色调、曝光、主导光源方向、色温、明暗基调 —— **跨组继承上一组已成立的视觉状态**。

### 3.7 `△` 使用规则（底座《镜头单元与△使用规则》）

> ⚠ **本条是「镜头死了」事故的根因条款**（见 §三.8）。原文把运镜写成**条件触发**，被读成
> 「不写 = 交给模型自由发挥」⇒ 实测 53 组只有 2% 的 `△` 写了运镜、0 处特写。

**正确读法：运镜描述是「默认动作」，不是「条件触发」，也不是「简单镜头可省」。**
必须另起 `△` 的情况：说话人切换且观看关系要变 / 情绪转折 / 关键物件进入 / 主体转换 / 遮挡转换。

### 3.8 ★ 镜头语言（跨制式通用层 ＋ 本制式 10 条）

**第一步 · 通用层（所有制式共用，2026-10-11 上浮）**：按 `references/镜头语言.md` 执行 ——
一镜三件套 / **运镜是戏剧任务的函数（⛔ 不设配额）** / 每个运镜交代落点 / 峰值镜头 /
跨组承接（景别与运镜**同时**承接）/ **反回声三类**。

**第二步 · 本制式细则**：`references/镜头语言.md`（10 条 ＋ 可脚本化自检）。

最小要求（10 条里的硬线）：

1. 每个 `△` 开头必须是 **「景别 ＋ 机位/角度」**，不只是景别；
2. **「固定」也要显式写**（不写运镜 ≠ 固定机位，模型会随机漂）；
3. 运镜写四件事：**围绕谁 / 从哪里观察 / 往什么方向动 / 落在什么画面重点**；
4. 一组之内景别要有**层级变化**（≥3 个 `△` 的组至少一次「近↔远」跳变）；
5. 切点落三种地方（说话人切换需新观看关系 / 情绪转折 / 关键物件进入），**不落在句号上**；
6. 特写**按需**（全篇 5–10 处，四种落点：关键道具 / 情绪转折 / 动作接触点 / 口播商品落点）；
7. **单 `△` 组是高危信号**（台词 ≥4 句至少 3 个 `△`；≥6 句至少 4 个 `△`）；
8. 首镜承接上一组末镜（见 §五）；
9. 每组定**一个峰值 `△`**，强度不平均分配；
10. **空间站位与跨组继承**（见 §五）。

★ **机器化门**：`tools/shot_language_check.py`（渠道无关，零计费）＝ 10 条的机器化版本；
⛔ 但它只查**形式**（写没写 / 密不密 / 重不重复），**条 5 / 8 / 9 / 10 必须人工核**。

### 3.9 适用例外（与「自己人」的分界）

`即梦25自己人.txt` **刻意把镜头调度权交给模型** ⇒ 镜头语言 10 条的**第 1/2/3 条不适用**，
第 4/6/7/8/9/10 条**仍适用**（它用【首尾定点】替代逐 `△` 机位）。详见 `制式-自己人.md`。

## 四、写词变体：简单版

★ **「简单版」不是渠道参数（不是 `--style` 的取值），是「正文写法变体」** ——
渠道侧用 `--style`/组名后缀选的是**跑哪张派生稿**，而简单版 = **改正文写法**。

- 权威稿：`即梦25简单提示词.txt`（由底座派生）。
- 形态：**扁平七字段镜头提示词**，完整保留底座的**判断方法论**，但**不输出**底座那套 `【】` 模块体系。
- 适用：不需要完整前置模块体系的**轻量跑批**场景。
- ⛔ 排除清单 / 输出格式以该派生稿 `〇.4` / `〇.5` 为准。

## 四·补 固定结尾与外挂（★ 2026-10-11 Q3 收敛结论）

**渠道提交时，由渠道程序把「固定结尾」自动外挂到正文之后**（底座已声明：各渠道成品提示词在提交时由渠道程序外挂）。
四份文件其实是 **2 份外挂结尾 ＋ 1 份写词附加约束 ＋ 1 份重复副本**：

| 角色 | 文件（`prompts/`） | 说明 |
|---|---|---|
| **外挂结尾 · 标准** | `即梦20固定提示词结尾.txt` | ★ **多渠道共用**（即梦系 ＋ 迪拜 ＋ vidu/器灵 均以此为准） |
| ↳ 同上（重复副本） | `即梦25固定提示词结尾_标准.txt` | ★ **与上一行逐字节相同**（md5 均为 `1cc96840099865ae78ce013c56212708`）—— 云鲸标准版按此名取用 |
| **外挂结尾 · 自己人** | `即梦25固定提示词结尾.txt` | 云鲸**自己人版**外挂结尾（md5 `8a6cdf42…`） |
| **写词附加约束**（⛔ 不是外挂结尾） | `标准后续固定语.md` | 拼在**写词阶段**的系统提示里（md5 `3a6c5ed3…`），**与视频外挂结尾是两回事** |

★ **收敛口径**：
1. **内容已收敛** —— 「标准」外挂结尾实际只有 **1 种内容**（上面那份逐字节相同的两份）；
2. ⛔ **不物理删除重复副本** —— `即梦25固定提示词结尾_标准.txt` 被 `core/jingyu_client.py`
   （`STYLE_STANDARD` 映射）与**历史用户项目的作业单**引用，删了会破坏旧产物可复现性；
3. ⇒ **纪律**：两份**同源，⛔ 禁止分头维护** —— 改一份必须同步另一份（对账判据：md5 必须相同）；
4. **渠道侧仍要声明「本渠道外挂哪一份」**（标准版渠道 → 那份共用标准结尾；自己人版 → 自己人结尾）。

## 五、跨组衔接与站位继承（★ 2026-10-10 上浮到主线 §二 Phase 6）

**所有用标准制式的渠道适用**，权威＝`即梦20镜头写作避坑.md` 第 8、10 条（H3 侧同源见 `H3多参提示词.md`）。

1. ★ **组首禁建镜** —— 同一连续事件相邻两组，本组**首镜承接上一组末镜**；
   ⛔ 不要每组都用远景/全景/建立镜开场、不要无理由推镜或拉镜开场。
   首镜景别由上一组末镜推导；**允许由远推近，禁止无理由由近拉远**；180° 轴线、朝向、视线、持物手跨组不变。
   **组尾**收在稳定、静态、信息完整的画面（⛔ 不收在大幅运动/甩镜/极端角度/过度虚焦里）。
2. ★ **站位与身体状态跨组继承** —— ① 真实空间 ≠ 画面左右；② 身体状态跨组继承；
   ③ 没入镜 ≠ 离场。站位只写「进入本组时已成立」的状态。

> ⚠ 这两条**无自动门** ⇒ 写完必须**人工对照上一组末镜**核组首。
