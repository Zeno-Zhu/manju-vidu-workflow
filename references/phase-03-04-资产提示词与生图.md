## ★★ 总分支：先查库，再谈生成（**顺序不许颠倒**）

```text
Phase 2 的资产盘点清单
   │
   └─ 逐项去通用资产库检索（asset_library_v1）
        │
        ├─ 库内【有】 ──→ ① 走 manju-asset-casting：重命名 + copy 进 01_资产库
        │                  ⛔ 不为它生成提示词、⛔ 不出图、⛔ 不"顺便重画一版"
        │
        └─ 库内【没有】─→ ② 生成提示词（按资产类型选对应规范）
                           → ③ 生图
                           → ④ 判断能不能收编进库（换个剧本还会用 → 收）
```

**为什么顺序不能颠倒**：库是**跨剧共用**的。自己重画会导致
① 同一角色在不同剧里长得不一样 ② 白烧一遍出图钱
③ 形态与库内不一致，**收不回库**，下次还得再画。

> ★ 真实事故：某项目绕开库、自己重画了一批「单角色图」，形态与库内资产完全不一致 ⇒ **整批作废**。

- ⛔ 跳过：`<项目>/00_剧本与提示词/_资产映射.json` 已存在且覆盖了全部资产。

**② 输入与权威规范**

| 类别 | 路径 |

**③ 做什么**（三步，每一步的命令见 `manju-asset-casting` §二）

| 步骤 | 命令 | 谁做 |
|---|---|---|
| ① 从剧本抽候选 | `python tools/pick_assets.py plan --script "<带时长剧本>" --top 3` | 确定性，零 LLM |
| ② 定映射 | 看 `plan` 输出，为每个线索**选一个**库内资产，写 `_选角映射表.json` | ★ **必须 AI 做** |

| ③' 落盘 | 加 `--apply` | 真复制 |

★ **`copy` 默认是预演（等价 dry-run）** —— 不加 `--apply` 什么都不改。
**先看预演报告再上 `--apply`。**

★ **身份轴守卫（P0 必拦 / P1 人工过）**：`copy` 会自动跑一次身份轴体检，
**P0 命中直接拦下不复制**；**P1（同性别近龄）不拦**，要人工看报告逐对确认。
- 配角优先用**功能角色**（`CHR_FUNC_*`）—— 不挂年龄身份轴，天然避开与主角的「同性别近龄撞脸」。

**④ 产出、命名与落位**

| 产物 | 路径 |
|---|---|
| 图片资产 | `<项目>/01_资产库/<语义名>.png` ← ★ **扁平，不按类型建子目录** |
| 音色 | `<项目>/01_资产库/<语义名>音色.wav` |
| 映射留痕 | `<项目>/00_剧本与提示词/_资产映射.json`（库内 id → 剧内名） |
| 提示词留痕 | `<项目>/00_剧本与提示词/_资产提示词/`（`--with-prompt` 时） |

## Phase 3B｜只为「库内没有的」生成提示词

**① 进入 / 跳过条件**
- 必须做：Phase 3A 已经走过，且**确实存在库内没有的资产**。
- ⛔ **跳过一整段**：盘点清单里全部资产都从库里取到了 ⇒ **不执行 3.1–3.5**。

**② 输入与权威规范 —— 按资产类型**选对文件**（★ 这是最常错的地方）

### ★★★ 开工前置（2026-10-15 补，血泪）：先读规范 ＋ 先定「全剧美术基调」

> **两份「设定版提示词规范」本身是「风格中立」的** —— 它们规定的是**结构**（模块、排版、
> 一致性、纯净规则、负面词），**不规定画风**。
> 角色版 §一「执行流程·第一阶段」、场景版 §十二「视觉风格要求」都把画风交给**输入**决定：
> 「先给出一个明确的**全剧人物主美术方向**」。
> ⇒ **画风 MUST 由项目侧作为输入提供**，否则 LLM 只能按模型先验自由发挥（写实模型 ⇒ 一律出写实）。

**三步前置，缺一不可：**

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| ① **读规范** | 开工前**必须通读** 4 份规范（`角色设定版提示词.md`／`场景设定版提示词.md`／`道具设定版提示词.md`／`角色基准图提示词.md`） | 它们是**唯一权威写作口径**；不读就只能靠模型先验瞎写 |
| ② **落一份「统一风格口径」** | 把系列/本剧的**固定风格主干 ＋ 本剧专属风格 ＋ 优先质感词**写成文档（如 `<项目>/00_剧本与提示词/_统一风格口径.md`） | 规范不管画风，画风必须有**唯一出处** |
| ③ **把风格口径当输入喂进 3.x** | ⚠ 工作流 3.x 的 `_script_summary()` **只喂剧本前 6000 字 ＋ 设定前 3000 字**，**不含任何画风信息** ⇒ 必须**另补**：临时把风格口径追加/内插进规范（跑完还原），或直接**确定性后处理** | 不喂 ⇒ 画风丢失，见下方"踩坑实录" |

★★ **风格串的「位置」也有讲究**：规范的结构是
`【资产类型】 → 角色身份 → … → 【背景与质感】 → 【负面约束】`。
**美术基调属于【资产类型】/开头**（先定调、再画人），**不要只在末尾追加** ——
末尾一句风格串会被前面一大段写实细节淹没。

★★★ **凡是「必须逐字出现」的内容（风格主干、固定资产 BASE 事实），一律不要交给 LLM 自由发挥。**
LLM 会漏、会改写、会自己发明（踩坑实录见下）。做法：
**LLM 出结构稿 → 确定性脚本注入/校验（grep 命中率必须 = 100%）→ 再落盘**。

#### 踩坑实录（2026-10-15，48 集项目，浪费一轮）
| 现象 | 真相 |
|---|---|
| 43 份产物的风格主干命中率 **0/43** | ① 规范本身不写画风 ② 3.x 不喂画风 ③ 把风格串追加在规范**尾部**，LLM 当成了"附加说明"直接无视 |
| 重跑一遍反而更糟：**所有角色都被写成「9:16 纯净基准图」** | 注入块里提到"重点角色才做基准图"，LLM 抓住了这个点 |
| 男主被写成 **178cm、纯黑发** | LLM 自己发明的，与固定资产 BASE（185cm＋前额银灰挑染）冲突 ⇒ **BASE 事实必须硬性写入并校验** |

### ★★ 出图模型必须与目标画风同族（2026-10-15 实测）

| 渠道／模型 | 实测画风 | 能否做 3D 国漫 |
|---|---|---|
| 大龙虾 `gpt-image-2.5` / `gpt-image-2.5-flare` | **照片写实**（连"纯风格串"提示词也只出真人感） | ⛔ **不能** |
| 迪拜3000 | 图像只有 `gpt-image-*` / `Midjourney-image`（`mj-*` 全是视频模型） | ⛔ 无 3D 国漫图像模型 |
| 中文系（即梦 family／Vidu 全能 Image 等） | 待测／按需验证 | ✅ 方向对 |

### ✅ 2026-10-18 外部实测修正（别把上面的结论当绝对）

另一条线（`stickman-science-workflow`，**极简 3D 火柴人：黑圆球头 + 细杆四肢 + 平涂**）实测：

| 项 | 结果 |
|---|---|
| 模型 | `gpt-image-2.5-flare-2k-16x9`（2048×1136） |
| 提示词 | "简化粗模 3D 火柴人动画风格：黑色圆球头、弧线式眼眉与嘴、细杆状四肢、深蓝色简化衣服壳；平涂材质、基础卡通阴影…浅灰纯色背景" |
| 耗时 | 单张 87.9 s |
| 结果 | ✅ 完全命中：黑圆球头、白弧线眼眉、细杆四肢、蓝色 T 恤短裤、柔和立体阴影、浅灰纯底 |
| 样图 | `stickman-science-workflow/runtime/gen-test/out/stickman_style_test.png` |

**结论要分层**：

- **写实度要求高的 3D 国漫人物**（要皮肤肌理、面部结构、PBR 材质）⇒ 原结论成立，`gpt-image` 会往真人靠，⛔ 不要用。
- **极简几何 + 平涂的卡通**（火柴人、简笔、扁平插画）⇒ **可以用**，反而落在 flare 模型能稳定输出的区间。
- `-2k-16x9` / `-9x16` 是 flare 的高分辨率变体，与基础 `gpt-image-2.5` **不是同一个模型**，不能用一个的结论否定另一个。

> ★ 通用的教训（比这条结论更有用）：
> **"某模型画风不行"这类结论，永远要带"测的是什么画风"这个前提。**
> 换画风之前先花一张图重测，不要直接搬旧结论 —— 这次就是差点因为旧记录否掉一条可用的渠道。

- ⇒ **定画风时同步定渠道**：3D／动漫／二次元项目**不要**用 OpenAI 系 `gpt-image`；
  它是写实取向，提示词再怎么堆风格词也掰不过来（实测 3 次：风格串在末尾／在开头／只给风格串，全部出真人感）。
- 判据：**先用「纯风格串 + 一句话主体」出一张样图**，1 分钟就能验渠道，别等整批跑完才发现画风错。

### ★★ 生图可以大量并发（2026-10-15）

- ⛔ 工作流 `core/media_task_runner.run_many_nodes()` **是写死的顺序 for 循环**（`max_workers=1`），
  `config.image.concurrency` **根本没被使用** ⇒ 43 张要跑 ~27 分钟。
- ✅ 生图是**纯网络等待**，天然可并发：自己起 `ThreadPoolExecutor(N)` 跑批即可。
  实测 **并发 12 → 22 张只要 1.5 分钟**（≈ 4 秒/张 等效）。
- ★ 并发时要**把产物清单（TaskRegistry）的写入留到最后单线程做**，避免并发写竞争。
- ⛔ 并发仅对**生图**；**生视频**要按各渠道的并发上限（见渠道差异层），不能照搬。

## ★ 2026-10-03 定案：设定版就是出片参考图（口径冲突已解决）

**出片参考图默认就用 `*_BOARD_*` 设定板** —— 不再另出「干净定妆图」，
也不再需要为「选设定版还是选定妆图」让用户拍板（`docs/经验与避坑.md` **G5**）。

前提：设定板按**新形态**产出 —— 把三类污染源从生产规范里移除：

## ★ 数量硬规矩（2026-10-11 定｜2026-10-15 修订）

### ★★ 只有「重点角色」才做 base 图（2026-10-15 用户定）

| 角色档位 | 是否出 base（基准图） | 做法 |
|---|---|---|
| **重点角色**（男女主、贯穿全剧的核心角色） | ★ **要** | 先出 base 固定本体 → 再拿 base 图生图出设定板 |
| **其他角色**（普通配角、功能角色、群像） | ⛔ **不要** | **直接出设定板**，一步到位；不搭 base、不做中间素材 |
| **已有固定资产 BASE 的角色**（系列男女主） | ⛔ **不要** | 直接用已提供的 BASE 当参考图出设定板 |

- 判据：**这个角色会不会在多集反复出现、并且需要长期稳定的脸？** 会 ⇒ 重点角色；只出现一两集 / 群像 ⇒ 直接出。
- ⇒ **Phase 3.4（角色基准图提示词）只对重点角色跑**，不要对全量角色跑（会白出一批用不上的 base）。

| 类型 | 出几张 | 做法 |
|---|---|---|
| **角色** | **能一张（不换装）满足使用，就只做一张**；要换装 / 有阶段形态 ⇒ **≤3 个设定板，优先 2 个** | 重点角色：**先 base → 拿 base 生成设定版**；其他角色：**直接出设定版** |
| **场景** | **一个地方一张** | 直接出 |
| **道具** | **一个道具一张** | 直接出 |

- ⛔ **base（基准图）后续生产不使用** —— 只是"固定本体"的**中间素材**，**只用来生成设定版**；
  出片要连的是**设定版**。

### ★★ 风格一致性：通用库不是万能的（2026-10-15 实测）

- 通用资产库 `asset_library_v1` 是**照片写实**口径（其 `docs/prompt_rules_v1.md` 明令"禁止…**3D渲染感**…"）。
- ⇒ **凡本项目走 3D / 动画 / 二次元等非写实画风，库内资产一律不可用**（角色脸、场景、道具都不行），
  必须按本剧风格重新生产 —— 否则成片会出现**写实与 3D 混剪**的风格割裂。
- ⇒ 接库前**先确认库的画风与本剧风格主干是否同族**；不同族就整段跳过 Phase 3A。

- 只做**盘点阶段结合剧本列出的**那些状态；**超出 3 个先与用户确认**。
- 命名：`<语义名>`；设定版带形态后缀（`林月华-婚礼`）。
- ★ **形象图文件名必须与 `_形象规划.json` 的 `file` 字段逐字一致**（含状态后缀）——
  改名先改规划再动文件；**规划里写了但还没生成的图，出片检查会一直拦**（这是有意的强制点）。
- ★ **设定版要以 base 为参考图生成**（图生图），提示词开头写明"严格参照已提供的角色基准参考图…"。
- ⛔ **角色音色不随服装 / 状态拆分**。
