## ★★ 总分支：先查库，再谈生成（**顺序不许颠倒**）

```text
Phase 2 的资产盘点清单
   │
   └─ 逐项去通用资产库检索（asset_library_v1）
        │
        ├─ 库内【有】 ──→ ① 走 manju-asset-casting：重命名 + copy 进 01_资产库
        │                  ⛔ 不为它生成提示词、⛔ 不出图、⛔ 不"顺便重画一版"
        │
        └─ 库内【没有】─→ ② 生成提示词（按资产类型选对应规范）
                           → ③ 生图
                           → ④ 判断能不能收编进库（换个剧本还会用 → 收）
```

**为什么顺序不能颠倒**：库是**跨剧共用**的。自己重画会导致
① 同一角色在不同剧里长得不一样 ② 白烧一遍出图钱
③ 形态与库内不一致，**收不回库**，下次还得再画。

> ★ 真实事故：某项目绕开库、自己重画了一批「单角色图」，形态与库内资产完全不一致 ⇒ **整批作废**。

## Phase 3A｜查库与接库（库内有的走这条）

**① 进入 / 跳过条件**
- 必须做：盘点清单里**每一项**都还没做过去库检索。
- ⛔ 跳过：`<项目>/00_剧本与提示词/_资产映射.json` 已存在且覆盖了全部资产。

**② 输入与权威规范**

| 类别 | 路径 |
|---|---|
| 输入 | `00_剧本与提示词/剧本/资产盘点.json`（Phase 2.3） |
| 输入 | `00_剧本与提示词/剧本/<项目名>剧本带对话时长.md` |
| ★ **通用资产库** | `asset_library_v1/`（**跨项目共用**） |
| **规范** | `manju-asset-casting` skill（取用侧主流程） |
| 索引 | `asset_library_v1/data/search_index_v1.tsv`（★ **只 grep 索引用，别读全量 JSON**） |

**③ 做什么**（三步，每一步的命令见 `manju-asset-casting` §二）

| 步骤 | 命令 | 谁做 |
|---|---|---|
| ① 从剧本抽候选 | `python tools/pick_assets.py plan --script "<带时长剧本>" --top 3` | 确定性，零 LLM |
| ② 定映射 | 看 `plan` 输出，为每个线索**选一个**库内资产，写 `_选角映射表.json` | ★ **必须 AI 做** |
| ②' 身份轴体检 | `python tools/pick_assets.py identity-check --map "<项目>/…/_选角映射表.json"` | 零改动干跑门 |
| ③ 复制进项目 | `python tools/pick_assets.py copy --project "<项目根>" --map "…"` ← **默认预演** | 预演 |
| ③' 落盘 | 加 `--apply` | 真复制 |

★ **`copy` 默认是预演（等价 dry-run）** —— 不加 `--apply` 什么都不改。
**先看预演报告再上 `--apply`。**

★ **身份轴守卫（P0 必拦 / P1 人工过）**：`copy` 会自动跑一次身份轴体检，
**P0 命中直接拦下不复制**；**P1（同性别近龄）不拦**，要人工看报告逐对确认。
- 配角优先用**功能角色**（`CHR_FUNC_*`）—— 不挂年龄身份轴，天然避开与主角的「同性别近龄撞脸」。

**④ 产出、命名与落位**

| 产物 | 路径 |
|---|---|
| 图片资产 | `<项目>/01_资产库/<语义名>.png` ← ★ **扁平，不按类型建子目录** |
| 音色 | `<项目>/01_资产库/<语义名>音色.wav` |
| 映射留痕 | `<项目>/00_剧本与提示词/_资产映射.json`（库内 id → 剧内名） |
| 提示词留痕 | `<项目>/00_剧本与提示词/_资产提示词/`（`--with-prompt` 时） |

- ⛔ **不要放进 `02_分集工程/`** —— 那里只放 `EPxx/` 视频，混进去会被出片脚本扫到。
- ★ **重命名是必须的**：提示词里写的是**剧内语义名**，文件必须同名，否则引用不成立。
- ★ **落位以项目实际为准**：库里来的走 `copy`（扁平）；**脚本生图的**落在
  `01_资产库/图片/<类型>/`。两种都合法，但**同一项目内保持一致**，别混着用。

**⑤ 闸门**
- **身份轴 P0** = 硬拦（`copy` 自动执行，无需人工）。
- **P1** = 人工确认（会在报告里逐对列出，标签「同性别近龄」）。

## Phase 3B｜只为「库内没有的」生成提示词

**① 进入 / 跳过条件**
- 必须做：Phase 3A 已经走过，且**确实存在库内没有的资产**。
- ⛔ **跳过一整段**：盘点清单里全部资产都从库里取到了 ⇒ **不执行 3.1–3.5**。

**② 输入与权威规范 —— 按资产类型**选对文件**（★ 这是最常错的地方）

| 资产类型 | ★ 权威规范（`prompts/`） | 产物形态 |
|---|---|---|
| 角色（设定版） | `角色设定版提示词.md` | 主角色锚点 ＋ 多视角/部件模块（★ 2026-10-03 起：不含表情模块、不含中文参数表） |
| 角色（基准图） | `角色基准图提示词.md` | ★ **纯净角色基准图**（先固定本体） |
| 场景 | `场景设定版提示词.md` | 场景设定版 |
| 道具 | `道具设定版提示词.md` | 道具设定版 |

> ★ **两个画幅是两件事，别混（2026-10-03 实测坐实，纠正一条历史误记）**

| 资产类 | 命名 | 画幅（实测） | 为什么是这个画幅 |
|---|---|---|---|
| **角色基准图** | `CHR_BASE_*` | **9:16 竖版 1136×2048**（22/22） | 单人全身直立 ⇒ 竖版才放得下、且与出片画幅同向 |
| **设定板**（角色/场景/道具） | `*_BOARD_*` | **16:9 横版 2048×1136**（252/252） | 一图多视角/多模块 ⇒ 横版才排得开 |

> ⚠ 历史笔记里曾把这两者记成"**规范写 9:16、实际是 16:9，互相打架**" —— **那是误记**：
> 规范与实际**都对**，只是**基准图和设定板本来就是两个画幅**。
> 判据：**看清你要出的是哪一类**（基准图 → 9:16 ｜ 设定板 → 16:9），不要拿一类的尺寸去校另一类。

> ★ **多版本角色的正确顺序**：**先出一张基准图固定本体**，各服装版本再各出一张
> **角色母资产设定板**；有基础版设定图的不重复描述五官。

**③ 做什么**

```bash
python main.py run --project "<项目名>" --step 3.1-3.5
```

| 步骤 | 做什么 | 用哪份规范 |
|---|---|---|
| 3.1 | 角色设定版提示词 | `角色设定版提示词.md` |
| 3.2 | 场景设定版提示词 | `场景设定版提示词.md` |
| 3.3 | 道具设定版提示词 | `道具设定版提示词.md` |
| 3.4 | 角色基准图提示词 | `角色基准图提示词.md` |
| 3.5 | 提示词清单汇总 | — |

**④ 产出**

- 提示词：`00_剧本与提示词/资产提示词/<类型>/<资产名>.md`（**一个资产一份**）
- ⛔ **不产出「单角色图」**（孤立单人棚拍 —— 无多视角、无部件模块、无标注）。
  它既**不是可复用资产**，也和库内形态不一致。
- ★ **给生成器的提示词别放进 `_资产提示词/`** —— 该目录同时存着 `copy --with-prompt`
  拷来的**库内提示词**，批量生成时会把库内提示词**连带重跑**（白烧钱）。
  **另开一个只放本次提示词的目录。**

**⑤ 闸门**
- 无独立门，但 **3.5 的提示词清单**是 Phase 4 的输入，漏资产在这里就能看出来。

## Phase 4｜生图

**① 进入 / 跳过条件**
- 必须做：Phase 3B 产出了提示词，且**存在要生成的资产**。
- ⛔ 跳过：全部资产都从库取到了 ⇒ 不进 Phase 4。

**② 输入与权威规范**
- 输入：Phase 3B 的提示词
- 规范：生图**渠道与模型**由 `项目配置.json` 的 `image.*` 决定
  （→ **合法模型名见当前渠道差异层**，⛔ 主线不写模型名）

**③ 做什么**

```bash
# 先 dry-run 验路，再去掉
python main.py run --project "<项目名>" --step 4.1-4.4 --dry-run
python main.py run --project "<项目名>" --step 4.1-4.4
```

| 步骤 | 做什么 |
|---|---|
| 4.1 | 角色基准图（9:16 @2K）← **前置 CP-2 硬门** |
| 4.2 | 角色设定版 |
| 4.3 | 场景设定版 |
| 4.4 | 道具设定版（完成后触发 CP-3 报告，非 gate） |

**④ 产出**
- `01_资产库/图片/角色基准/`、`图片/角色/`、`图片/场景/`、`图片/道具/`
- 断点续跑：**已存在且 >1KB 的产物自动跳过**，重复执行不重复花钱。

**⑤ 闸门**

| 门 | 时机 | 类型 | 谁批 | 没过怎么办 |
|---|---|---|---|---|
| ★ **CP-2 基准图素材确认** | **4.1 之前** | 🔒 **gate** | **用户** | 未批准**不生成**基准图 |
| CP-3 生图结果确认 | 4.4 之后 | 报告 | 用户 | 逐张核对来源 / 尺寸 |

★ **CP-2 的用法**：用户可先把**商品基准图 / 重点角色基准图**放进项目资产目录的
`用户上传/` 下，报告里会标 ✅，**已有的不会重复生成**。两级目录按类型分开：

| 放什么 | 放哪 |
|---|---|
| 角色基准图 | `01_资产库/图片/角色基准/用户上传/<角色名>.png` |
| 道具 / 商品基准图 | `01_资产库/图片/道具/用户上传/<商品名>.png` |

> ★ **文件名必须是项目内语义名**（与提示词里写的一致），否则报告匹配不上、会被当成"缺图"重复生成。

```bash
python main.py check --project "<项目名>" --point 2            # 看 CP-2 报告
python main.py check --project "<项目名>" --point 2 --approve  # 批准，然后重跑 4.1
```

## ★ 2026-10-03 定案：设定版就是出片参考图（口径冲突已解决）

**出片参考图默认就用 `*_BOARD_*` 设定板** —— 不再另出「干净定妆图」，
也不再需要为「选设定版还是选定妆图」让用户拍板（`docs/经验与避坑.md` **G5**）。

前提：设定板按**新形态**产出 —— 把三类污染源从生产规范里移除：

| 移除的内容 | 原来的害处 |
|---|---|
| 中文参数表 / 左侧信息栏 | **抢台词预算** |
| 表情示例模块 | **表情照搬** |
| 一图多脸（面部近景×3 ＋ 表情×4） | **年龄漂移 / 身份锚丢失** |

规范：`prompts/角色设定版提示词.md` 第九/十/十三/十八节。

**存量旧形态图照用不重做**；个别实测画面明显坏的角色，单独重出该角色设定板。

## ★ 数量硬规矩（2026-10-11 定）

| 类型 | 出几张 | 做法 |
|---|---|---|
| **角色** | **能一张（不换装）满足使用，就只做一张**；要换装 / 有阶段形态 ⇒ **≤3 个设定板，优先 2 个** | **先 base（基准图）→ 下载 → 拿 base 生成设定版** |
| **场景** | **一个地方一张** | 直接出 |
| **道具** | **一个道具一张** | 直接出 |

- ⛔ **base（基准图）后续生产不使用** —— 只是"固定本体"的**中间素材**，**只用来生成设定版**；
  出片要连的是**设定版**。
- 只做**盘点阶段结合剧本列出的**那些状态；**超出 3 个先与用户确认**。
- 命名：`<语义名>`；设定版带形态后缀（`林月华-婚礼`）。
- ★ **形象图文件名必须与 `_形象规划.json` 的 `file` 字段逐字一致**（含状态后缀）——
  改名先改规划再动文件；**规划里写了但还没生成的图，出片检查会一直拦**（这是有意的强制点）。
- ★ **设定版要以 base 为参考图生成**（图生图），提示词开头写明"严格参照已提供的角色基准参考图…"。
- ⛔ **角色音色不随服装 / 状态拆分**。
