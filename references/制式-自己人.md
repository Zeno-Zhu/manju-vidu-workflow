**锚定主线版本**：`2026-10-10`

## 一、这是什么制式（★ 反向范式，别照搬标准）

**自己人 = 把镜头调度权交给模型**：正文用「自己人导演讲戏」的方式写**说明书** ——
讲清**现场事实**（发生在哪、人物此刻在哪、谁在做什么、关系压力、刺激怎么进入、行为怎么变、声音/物件/视线怎么相互作用），
**普通镜头选择（景别 / 构图 / 运镜）交给模型**。

> ★★ **本制式与「标准」是两套反向范式**，⛔ **不能互相照搬**：
> - **标准**：写稿人控镜头 ⇒ 每个 `△` 必须显式「景别 ＋ 机位/角度 ＋ 运镜」。
> - **自己人**：模型控镜头 ⇒ **正文里不逐镜规定机位**，但**组边界的落点必须可控**（用【首尾定点】，见 §三.2）。
>
> ⇒ 标准制式的**镜头语言 10 条中，第 1/2/3 条（每 `△` 必须写景别＋机位/运镜）对自己人不适用**；
> **第 4/6/7/8/9/10 条仍然适用**（层级变化 / 特写按需 / 单镜组高危 / 峰值 / 跨组衔接 / 站位继承）。

**语法形态**：**散文（无 `△`）** —— 正文是连续段落，不逐镜标注。
（例外：H3 侧自己人仍是 H3 输出协议，正文散文但保留六字段与必要 `[Shot N]`，见 §四。）

**覆盖渠道**：本包 = Vidu
（渠道侧自己声明「本渠道用自己人制式」；权威路由见 `routing-table.md`。）

## 三、共用方法论（跨渠道不变）

### 3.1 核心原则（两张稿共同）

1. **完整承接**上游意图：核心剧情、人物设定、人物关系、台词、叙事节点、分镜拆解逻辑，**一个不动**。
2. 按**单个分镜组**独立输出，一组一个代码块，**独立完成资产盘点**。
3. 正文用「**讲戏**」语气：**少讲抽象情绪，多讲演员真实可见的行为 / 声音关系 / 空间事实 / 持续状态**，点到为止。
4. **相信模型**具备导演 / 镜头组织 / 景别选择 / 运镜判断能力 —— **普通镜头选择权交给模型**；
   但**剧情事实、空间事实、人物关系、声音关系、行为连续性必须写明确**，不交给模型猜。
5. **只围绕本组有效点写**：不为画面丰富加无关人物/动作/环境；也不为精简删掉影响连续性的事实。
6. 严格使用**用户提供的资产名**，不擅自增删/缩写/翻译/改名。
7. 最终**只输出一级集标题 ＋ 提示词代码块**，不输出分析/解释/自检。

### 3.2 ★【首尾定点】—— 自己人的「可控边界」机制

自己人把中间镜头完全交给模型，但**组边界必须可控**，所以正文**必须显式给出【首镜】与【末镜】两笔**：
写清**景别、主体、机位方向**，以及该镜的关键状态（朝向 / 持物 / 身体姿态 / 与他人的距离）。
中间镜头只写**必须完成的动作节点、台词进入方式、现场反应**，不规定机位与切法。

- **【首镜】** 任务＝**承接上一组末镜**（见 §五）；本场景第一组才负责交代地点与人物关系。
- **【末镜】** 任务＝**留下落点**：收在稳定、静态、信息完整的画面（⛔ 不收在大幅运动/甩镜/极端角度/过度虚焦里）；
  末镜同时是下一组【首镜】的继承依据。

### 3.3 气质与质感（沿用「统一风格模块」，写法不同）

- **质感**：8K 电影级画质、自然动态模糊、适度胶片颗粒；色彩影调贴合场景且全程统一；高光保结构、暗部不死黑。
- **人物表现**：形象一致、表演有呼吸感；★ **不同角色的情绪反应必须可区分**（不得所有人同一种表情/小动作）；
  ⛔ 禁止同一人物同画面出现分身、群像中不得重复出现主要参考角色。
- **镜头与节奏**：统一匹配专业电影机镜头质感；**开篇禁快速大幅运镜与大景别突变**；全程无跳轴；
  **非必要不设空镜**，如必需单个空镜 ≤1.6s；结尾音频气口自然完整。
- 【同期声说明】控制在一至两句话；【强制声明】无 BGM、画面无字幕/文字/水印/Logo/角标/UI。

## 三·补 ★ 人物外观只做「资产绑定」，⛔ 不写外貌（2026-10-12）

自己人版**同样适用**：已有角色视觉资产时，外观**全部交给参考图** ——
⛔ 不写五官 / 体型 / 发型 / 服装款式 / 服装颜色 / 固定配饰。
理由：文字**上限 = 与图一致（零增益）**，**风险无上限**（与图不符 → 矛盾指令 → 人物 / 服装漂移）。
**例外**：服装 / 配饰**特写**或需**材质质感**时可写材质，⛔ 仍不写颜色与形态。
权威：本包规范稿 `prompts/自己人模板提示词.md`（人物固定外观边界）｜落地 `制式-标准.md` §3.3。

## 四、输出模板差异（语法层，两侧各留）

| 维度 | 即梦系（`即梦25自己人.txt`） | H3 系（`h3自己人.md`） |
|---|---|---|
| 正文 | **散文（无 `△`）** | **散文**，但保留 H3 输出协议（六字段） |
| 镜头标记 | 无 `△` | 保留 `[Shot N]`，但**能由一个连续摄影过程完成的内容优先保持在一个 Shot**；仅在真实独立切镜/时空跳转/观看关系必须变/超单镜承载时才新建 `[Shot N]` |
| 资产/参考 | 沿用即梦系的 `【】` 模块（基础信息/统一风格/资产盘点/…） | 沿用 H3 的 `Reference` / `Skill Reference` 判断 |
| 边界 | 【首尾定点】 | 【首尾定点】＋ H3 的 `group_duration` 与单组时长上限 |

> ⛔ 两侧的**字段名与载荷**不要互抄；渠道差异层声明本渠道走哪侧、外挂哪张稿。

## 四·补 ★ 镜头语言（跨制式通用）

自己人把**中间镜头交给模型**（`即梦25自己人.txt`），但**边界与分布仍受通用层管**：
按 `references/镜头语言.md` 执行 —— 一镜三件套 / **运镜是戏剧任务的函数（⛔ 不设配额）** /
每个运镜交代落点 / 峰值镜头 / **反回声三类**（组内连续 ≥3 镜同「景别+运镜」、相邻组首镜连续同、全季高频套件）。

自己人的特殊之处：中间镜头由模型调度，**组首 / 组尾的景别与运镜必须写死**（见 §3.2 首尾定点）。
⛔ 不因为"中间交给模型"就对首尾放水 —— **模型自由度越大，边界越要钉死**。

---

## 五、跨组衔接与站位继承（与标准同源，两制式共用）

与 `制式-标准.md` §五 **同一条**：组首承接上一组末镜（组首禁建镜）＋ 站位与身体状态跨组继承。
自己人因为「中间镜头交给模型」，**组首/组尾的落点比标准更重要**（模型自由度越大，边界越要钉死）。

## 六、边界（⛔ 本文件不含的东西）

- **不含渠道取值**（模型名 / 端点 / 参数上限 / 计费 / 失败信号）—— 在对应渠道差异层。

- **不重复「标准」制式的内容** —— 分层万能公式 / 时长容量 / 红线细节见 `制式-标准.md`。
