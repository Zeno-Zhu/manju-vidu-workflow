# 资产整理（客户目录"乱"怎么办）

<!-- (c) manju-vidu-workflow · MJVID:fe400bd5f9 · 溯源标记请勿删除 -->

> 客户拿来的项目目录**通常不是我们想要的样子**。典型长这样：
>
> ```
> <项目>/
> ├── 00_剧本与提示词/  01_资产库/  02_分集工程/  …   ← 我们的标准目录（在）
> ├── 护士三视图.png  老太太三视图.png  管家三视图.png  …   ← 一堆图散在根层
> ├── 人物定妆照/  人物介绍/  视频素材/  故事板1.png …
> └── 人物小传.docx  富二代开车撞我试试·人物小传.docx …
> ```
>
> 本文件说明**怎么把它们归位**。★ 原则：**只搬不删、先方案后执行、用户原图留档**。

---

## 一、目标结构（唯一口径，见 `references/flow.md` §1）

```text
<项目>/
├── 00_剧本与提示词/剧本/            剧本 / 分集大纲 / 人物小传 / 设定等文档
├── 00_剧本与提示词/EPxx/            分镜组表 / 制作规划 / 资产盘点 / 故事板
├── 01_资产库/用户上传/              ★ 用户给的原始件（三视图 / 定妆照 / 参考图 / 文档）
├── 01_资产库/图片/                  可用的角色/场景/道具图（语义名）
├── 01_资产库/音色/                  音色参考
├── 02_分集工程/EPxx/视频/           成片
├── 03_背景音乐/  04_最终交付/  _出片记录/
```

---

## 二、归类规则（工具按"关键词 + 扩展名"判，认不出就**不猜**）

| 现位置/文件名 | 归到 | 说明 |
|---|---|---|
| 含「**故事板 / storyboard / 分镜图**」的图片 | `00_剧本与提示词/EPxx/故事板/` | 分镜图属**信息类产物** |
| 含「**剧本 / 分集 / 大纲 / 人物小传 / 人物介绍 / 设定**」的文档或图 | `01_资产库/用户上传/` | 原始资料留档 |
| 含「**音色 / 配音**」的音频 | `01_资产库/音色/` | |
| 其它 **图片**（三视图 / 定妆照 / 角色图 / 场景 / 道具） | `01_资产库/用户上传/` | 原图留档 |
| 其它 **音频** | `01_资产库/音色/` | |
| **视频**（.mp4/.mov…） | `01_资产库/视频素材/` | 参考片、素材 |
| 其它 **文档** | `01_资产库/用户上传/` | |
| **认不出来的** | ⛔ **不动**，列进《待确认》 | 由人判断 |

**图片会"留两份"**：原件进 `用户上传/`（**不覆盖、不改动**），另**复制**一份进 `图片/` 供后续使用
—— 这是规范要求：用户的图**只留档不"标准化"**。

---

## 三、安全约定（硬规矩）

1. **默认只出方案**（dry-run），**不动任何文件**；看完《资产整理方案.md》再加 `--apply`。
2. **只搬不删** —— 永不删除用户文件；重名自动加 `_2`、`_3`。
3. 搬空后剩的**空目录不删**，只在报告里列出来，让用户自己决定。
4. 标准目录（`00_/01_/02_/03_/04_/_出片记录/`）**原样不动**。
5. **整理 ≠ 选角**：本步只做"归位"。**语义命名 / 选角 / 定妆**属**阶段 3 资产核对**，另做。

## 四、命令

```bash
# 只出方案（推荐先跑这个）
python scripts/organize_assets.py --project "<项目目录>"

# 确认后执行
python scripts/organize_assets.py --project "<项目目录>" --apply

# 故事板归属到指定集
python scripts/organize_assets.py --project "<项目目录>" --ep 2 --apply
```

- 方案落盘：`<项目>/_出片记录/资产整理方案.md`（含逐条"现位置 → 归到 → 依据"）。
- 返回 JSON 里的 `report_text` 就是这份方案，可直接贴给用户确认。

## 五、和流程的关系

```text
阶段 0 初始化（建标准目录）
   ↓
阶段 2 资产盘点（读剧本，列出"这部戏需要什么"）
   ↓
★ 资产整理（把客户乱目录归位 —— 本文件）   ← 客户目录乱时才做
   ↓
阶段 3 资产核对（谁有 / 谁缺 / 谁待确认；语义命名、选角）
   ↓
阶段 4 资产生成（缺的才补）
```

> ★ **顺序很重要**：先归位再核对，否则"谁有"会被一堆散文件搞晕。
> ★ **对用户**只说结论：整理完了、哪些归位到哪、哪些没认出来要他确认 —— **不要**罗列内部规则。
