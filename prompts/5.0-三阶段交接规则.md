# Phase 5.0｜三阶段交接规则与程序控制点

> 本文是 **5.1 / 5.2 / 5.3 三套提示词**的调用层约定。
> ★ 核心原则：**每个阶段只生产自己负责的新增决策，已确认信息引用上游、不重新生成一份。**
> ⛔ 不新增"负责反复总结规划"的 AI 阶段 —— 交接靠**约定 + 程序**。

---

## 一、上下游交接表

| 交接 | 上游提供 | 下游新增决策 |
|---|---|---|
| **5.1 → 5.2** | 原剧本、有效 TSV、场景映射 | 真实现场、人物状态、必要事件 |
| **5.2 → 5.3** | 统一制作基准、**组末约束** | 逐 Shot 动作落位和摄影 |
| **5.3 → Phase 6** | 镜头 TSV、剧本单元、**状态快照（程序算）** | 模型专用提示词正文 |
| **Phase 6 → Phase 7** | 最终提示词、资产绑定、**版本** | 校验和实际生成 |

**产物对照**

| 阶段 | 唯一正式产出 | 形态 |
|---|---|---|
| 5.1 | `EPxx_分镜组.tsv` | 三列（分镜组ID / 时长 / 原剧本锚点） |
| 5.2 | `EPxx_统一制作基准.md` | 人读 Markdown（连续现场 + 初始状态 + 分组规划） |
| 5.3 | `EPxx_镜头规划_{制式}.tsv` | 八列（含状态变化事件） |
| 程序 | `EPxx_连续性.json` | **程序算**的每组初态/末态快照 |

## 二、三个程序控制点（★ 不新增 AI 阶段）

### 控制点 A｜5.1 完成后 —— 建立可核验的剧本单元

**做什么**：按 TSV 里的 `start:` / `end:` 锚点在原剧本中定位分组，生成**可复现的对白 / 动作单元 ID**：

```
A001 → 某个原始动作单元
L001 → 某句原始对白
```

并核实**原文覆盖关系**（无遗漏、无重复、顺序正确）。

**为什么**：5.3 只引用单元 ID、不复制原文；如果锚点重复或定位含糊，问题会一路传到 5.3 变成"台词对不上"。
**⛔ 就在这一关修，不要把含糊定位传下去。**

### 控制点 B｜5.3 完成后 —— 合并验证 + 状态快照

**做什么**：对三份产物做一次合并验证 ——
**时间结构来自 5.1、分组结果的约束来自 5.2、真实事件发生时点来自 5.3**。
程序据此**计算每组开始和结束状态**（`group_start_state` / `group_end_state`）。

**核对项**：
1. Shot ID 合法性与 5.1 集合逐项匹配；
2. 台词 / 动作单元覆盖；
3. **同一句跨 Shot 的音频连续性**；
4. 景别 / 机位 / 运镜字段完整性；
5. 状态事件解析（语法合法性）；
6. ★ **状态转移合法性** —— 如"上一组末态=坐，本组要求站且无 `stand()` 事件" ⇒ 报
   `POSTURE_TRANSITION_MISSING`；
7. ★ **与 5.2 的「组末必达」核对**。

> ⚠ **不要让校验器自动补动作**（例如自动补一句"他起身了"）—— 那可能篡改剧本。
> 正确做法是**回到 5.2 确认**：究竟是漏了动作，还是下一组的提示词写错了。

### 控制点 C｜Phase 6 生成前 —— 最小充分输入 + 版本锁定

**做什么**：按组编译**最小充分**的写词输入，只包含：

- 当前剧情；
- 该组 Shot 时间与对应摄影行；
- 人物**当前**初始状态；
- 相关资产；
- 必要的上一组摄影衔接。

并**保存输入版本**（版本号 / 哈希），防止规划改了却仍用旧提示词。

## 三、数据一致性规则

1. **结构化数据是源头，提示词是派生结果** —— ⛔ 提示词不应反过来成为事实来源。
2. **真实空间 ≠ 画面空间** —— 「画面左/中/右」「前中后景」属摄影层（5.3 才用），
   ⛔ 不能当作跨组永久站位。真实位置用空间锚点（`沙发左座` / `茶几靠门侧` / **`角色A对面`**）。
3. **人物状态：AI 规划变化，程序负责继承** —— 不再让 AI 承担跨组记忆的责任。
4. **同一份权威文件** —— 修订必须回写权威文件（5.1 TSV / 5.2 基准），⛔ 不创建并行版本。
5. **提示词记录自己的状态版本** —— 版本不一致就阻断出片或要求重新生成。

---

## 四、拆分次数的选择

默认采用**三个独立逻辑步骤**，但**不强制三个步骤一定调用三个不同模型**：

- **简单场景**：5.2 与 5.3 可以在**同一个会话中顺序执行**并分别落盘；
- **多人场面 / 复杂动作 / 长镜头 / 特殊奇观**：**分开调用更可靠**。

> 这一版的核心是**保留真正的导演工作，而不重复制造数据**：
> **5.1 负责时间与结构，5.2 负责真实现场与连续性，5.3 负责可执行的联合摄影设计，Phase 6 负责最终的视频模型表达。**
